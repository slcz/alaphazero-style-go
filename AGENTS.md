- Performance is critical.
- When discussion with user, keep it clean and direct. Reduce verbosity.

This is the high level requirement:
- Similar as https://github.com/slcz/chess, jump start Go game from scratch to a reasonable amateur level.
- The chess repo is local at /Users/sileizhang/chessgui. Reuse as much as possible: port the engine (puct.c MCTS/RPO, selfplay.c, nn_eval.c, shard format) and the Python side (nn_worker, trainer, selfplay_loop), swapping only the rules seam (chess.h/board.c/movegen.c/termination.c -> TT rules) and the net's heads/encoder. GUI/wasm/ONNX/sf_gauntlet/opening book are not ported.
- Platform: train/selfplay on x86 + RTX 5090 (CUDA). Play on local Mac M4 (MPS). Both paths already exist in chess nn_worker.
- Achieving absolute high level is not the goal. The priority is, 1) very minimum rules and almost zero domain knowledge. 2) compute resource must be utilized efficiently. as in chess project, we'll probably just train/selfplay with single 5090 card system.
- Play rules are Tromp-Taylor rules.
    - Chess engine's rules are replaced with TT (tromp-tylor) rule. scoring is also strict TT rule, when 2 party pass or when the max plys reached, use TT to score.
    - Superko legality is handled by masking illegal moves at the policy head output (same as chess). No ko/illegal input plane.
    - Selfplay komi: 9.5 for 7x7, 7.5 for 9x9 and 19x19. Always fractional so the win/loss value head never sees a tie (jigo).
- Key features I think we need,
    - Playout Cap Randomization (already used in chess)
    - MCTS multiple walkers, dual bank rows, multiple threads almost no change from chess code
    - Use RPO (regularized policy optimization), this is already implemented in puct.c
    - Implement GTP protocal, only the required supported subset. No need to support GUI, wasm, so these code should not be ported over.
        - required GTP commands. protocol_version, name, version, known_command, list_commands, quit, boardsize, clear_board, komi, play, genmove
    - Network is transformer based, as a matter of fact, we can reuse most of the trunk (d=256, head = 8, 8 layers transformers, ff=1024, etc.)
    - Rope 2D but only x and y 2 directions instead of 4 (no diagnol). RoPE uses raw integer coordinates (distance-1 = adjacency at every board size); only the edge-distance planes normalize by board size.
    - Transformer must be designed to adapt to different board size (7x7, 9x9, ... 19x19). THis means the same weights should be resusable from one size to another. We only support square boards.
    - Katago paper (downloaded) listed input features. Here is what we need,
        - own/opponent stone planes (2)
        - last 5 move location planes one-hot encoding (5)
        - some knowledge of edge. we can encode a minimum distance to left/right edge and top/botom edge (4 planes). Normalized by the board size.
        - scalar channels, which of the previous 5 moves were pass? Komi/15.0. But we don't need others. Board size divided by 19.
    - Katago paper listed loss functions. Rememeber we don't use convolution. Here is what we need,
        - policy head (mlp d to 1), and value head (one hot win/loss, no tie)
        - ownership head (similar as policy head without pass)
        - score heads, pdf and cdf. Size-agnostic fixed 1-point bins covering up to +/-(19*19+komi+slack) ~ +/-370, so the same head works for all board sizes.
        - aux head (used in chess as well) for opponent policy loss
- The strategy,
    - start with 7x7 board, to train the network to learn the end game and basic value. We set maxply to around 150, once the maxplys reached or both party pass, use TT rule to calculate score (in selfplay, and self eval). Once this is trained reasonably well, we turn on the fast play mode that only uses policy network without search (nsim=0) and enable the fast play mode when the value network indicates high confidence of win/loss (say 0.95) in selfplay.
    - Only high-budget (full search) plies are used for training. Low-budget PCR plies and nsim=0 fast-play plies are recorded in the game record shard but not trained (same as KataGo paper's PCR semantics).
    - once we have a decent 7x7, move to 9x9 and larger board size.
    - In evaluation game, we still allow resign. However this is controlled by the engine driver. When network returns high confidence of win/loss, it automatically resigns.
